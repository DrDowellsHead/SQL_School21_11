ПОДГОТОВКА БАЗЫ ДАННЫХ К ПРОВЕРКЕ DAY08
===========================================

Важно:
- задания ex00-ex07 проверяются последовательно;
- между заданиями базу сбрасывать не нужно;
- для демонстрации параллельных транзакций нужны две разные сессии PostgreSQL;
- разные пользователи PostgreSQL не обязательны: можно открыть две сессии от имени postgres;
- SQL-файл упражнения нельзя запускать целиком в одном терминале, потому что команды должны чередоваться между Session #1 и Session #2.


1. УЗНАТЬ ИМЯ ТЕКУЩЕЙ БАЗЫ
---------------------------

Выполнить в PostgreSQL:

SELECT current_database(), current_user, pg_backend_pid();

Запомнить значение current_database. В командах ниже вместо YOUR_DATABASE необходимо подставлять это имя.


2. ЗАКРЫТЬ НЕЗАВЕРШЁННЫЕ ТРАНЗАКЦИИ
------------------------------------

В обоих открытых сеансах выполнить:

ROLLBACK;

Если активной транзакции нет, PostgreSQL выдаст предупреждение. Это нормально.


3. ВЕРНУТЬ PIZZERIA В СОСТОЯНИЕ ПЕРЕД EX00
-------------------------------------------

В одном сеансе выполнить:

BEGIN;

DELETE FROM pizzeria
WHERE (id = 10 AND name = 'Kazan Pizza')
   OR (id = 11 AND name = 'Kazan Pizza 2');

UPDATE pizzeria
SET rating = 4.6
WHERE id = 1
  AND name = 'Pizza Hut';

COMMIT;

Этот запрос:
- удаляет Kazan Pizza, добавленную в ex05;
- удаляет Kazan Pizza 2, добавленную в ex06;
- возвращает Pizza Hut исходный рейтинг 4.6;
- не удаляет накопленные изменения из предыдущих проектов.


4. ПРОВЕРИТЬ ИСХОДНОЕ СОСТОЯНИЕ
--------------------------------

Выполнить:

SELECT *
FROM pizzeria
ORDER BY id;

Должно остаться 6 строк:
1 | Pizza Hut  | 4.6
2 | Dominos    | 4.3
3 | DoDo Pizza | 3.2
4 | Papa Johns | 4.9
5 | Best Pizza | 2.3
6 | DinoPizza  | 4.2

Дополнительная проверка:

SELECT
    COUNT(*) AS pizzeria_count,
    SUM(rating) AS total_rating
FROM pizzeria;

Ожидается:
pizzeria_count = 6
total_rating = 23.5


5. ОТКРЫТЬ ДВЕ СЕССИИ POSTGRESQL
---------------------------------

В VS Code открыть два терминала:

Terminal -> New Terminal
Terminal -> New Terminal

В первом терминале выполнить:

psql -h localhost -p 5432 -U postgres -d YOUR_DATABASE

Во втором терминале выполнить ту же команду:

psql -h localhost -p 5432 -U postgres -d YOUR_DATABASE

Например, для базы sqlb4_dml:

psql -h localhost -p 5432 -U postgres -d sqlb4_dml

Если локальное подключение настроено через системного пользователя Ubuntu:

sudo -u postgres psql -d YOUR_DATABASE


6. УБЕДИТЬСЯ, ЧТО СЕССИИ РАЗНЫЕ
--------------------------------

В каждом терминале выполнить:

SELECT current_database(), current_user, pg_backend_pid();

current_database и current_user могут совпадать.
Значения pg_backend_pid() должны различаться.

Для удобства изменить приглашение первого терминала:

\set PROMPT1 'Session1 %n@%/%R%# '

Во втором терминале:

\set PROMPT1 'Session2 %n@%/%R%# '


7. ПРОВЕРЯТЬ ЗАДАНИЯ ПО ПОРЯДКУ
--------------------------------

Выполнять задания последовательно: ex00 -> ex01 -> ex02 -> ex03 -> ex04 -> ex05 -> ex06 -> ex07.

Ожидаемое состояние после каждого задания:

Перед ex00:
Pizza Hut = 4.6
Количество пиццерий = 6
Сумма рейтингов = 23.5

После ex00:
Pizza Hut = 5

После ex01:
Pizza Hut = 3.6

После ex02:
Pizza Hut = 4

После ex03:
Pizza Hut = 3.6

После ex04:
Pizza Hut = 3.0

После ex05:
Добавлена Kazan Pizza с id = 10 и рейтингом 5.
Сумма рейтингов = 26.9

После ex06:
Добавлена Kazan Pizza 2 с id = 11 и рейтингом 4.
Сумма рейтингов = 30.9

После ex07:
Данные не изменяются. Воспроизводится deadlock.


8. КАК ВЫПОЛНЯТЬ ШАГИ В ДВУХ СЕССИЯХ
-------------------------------------

Комментарии в файлах day08_ex00.sql - day08_ex07.sql указывают, в каком терминале выполнять команды:

- Session #1 -> первый терминал;
- Session #2 -> второй терминал.

Нельзя запускать весь файл одной командой в одном терминале.
Нужно выполнять блоки по очереди в соответствии с номерами шагов.

Если команда UPDATE ожидает завершения другой транзакции:
- не прерывать ожидающую команду;
- перейти во второй терминал;
- выполнить следующий шаг COMMIT, ROLLBACK или встречный UPDATE;
- вернуться в первый терминал.


9. ПОДКЛЮЧЕНИЕ ДВУХ РАЗНЫХ ПОЛЬЗОВАТЕЛЕЙ
-----------------------------------------

Для задания это необязательно. Две сессии одного пользователя postgres уже являются независимыми.

Если нужны именно разные пользователи, подключиться администратором:

psql -h localhost -p 5432 -U postgres -d YOUR_DATABASE

Создать роли:

CREATE ROLE session1 LOGIN PASSWORD 'session1_password';
CREATE ROLE session2 LOGIN PASSWORD 'session2_password';

Разрешить подключение к базе. В следующей команде заменить sqlb4_dml на настоящее имя базы:

GRANT CONNECT ON DATABASE sqlb4_dml TO session1, session2;

Выдать права:

GRANT USAGE ON SCHEMA public TO session1, session2;

GRANT SELECT, INSERT, UPDATE, DELETE
ON ALL TABLES IN SCHEMA public
TO session1, session2;

После этого открыть два терминала.

Первый терминал:

psql -h localhost -p 5432 -U session1 -d YOUR_DATABASE

Второй терминал:

psql -h localhost -p 5432 -U session2 -d YOUR_DATABASE


10. ПОЛНОЕ ВОССТАНОВЛЕНИЕ В НОВОЙ БАЗЕ
---------------------------------------

Использовать только тогда, когда текущей базе уже нельзя доверять.

Создать отдельную базу:

createdb -h localhost -p 5432 -U postgres sqlb8_check

Загрузить исходную модель:

psql \
    -h localhost \
    -p 5432 \
    -U postgres \
    -d sqlb8_check \
    -v ON_ERROR_STOP=1 \
    -f /absolute/path/SQL_School21_11/materials/model.sql

Важно:
- materials/model.sql не удаляет существующие таблицы;
- его нельзя повторно запускать в заполненной базе без предварительной очистки;
- после создания базы с нуля необходимо восстановить накопленные изменения Day03 ex07-ex13 и изменение Day04 ex07;
- поэтому для обычной повторной проверки Day08 предпочтительнее использовать шаги 2-4 этой инструкции.


11. ЗАВЕРШЕНИЕ РАБОТЫ
----------------------

Выйти из psql:

\q

Если после проверки нужно повторить весь Day08, снова выполнить шаги 2-4.
